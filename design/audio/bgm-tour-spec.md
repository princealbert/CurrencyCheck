# 1. 决策：为什么新编，而不是复用 `bgm_codex`

`world-tour-reward.md` §5 的原建议是复用 `bgm_codex`（gain 0.42），并把「循环点可能落在字幕中段」列为主要风险。**实测后这条风险论据不成立，但结论仍然成立**——真正的理由是另外三条，而且更硬。

**先纠正一个事实**：`bgm_codex.mp3` 实测时长 **114.8s**。33 秒的影片根本跑不到循环点，「循环点落在字幕中段」这件事不会发生。请不要再用这条理由对外解释，它经不起复核。

真正成立的三条理由：

### 1.1 没有终止式 —— 影片会「被掐断」，而不是「收住」

复用 codex = 取它 114.8s 里的**任意前 33 秒**。这 33 秒的结尾必然落在一个乐句中间。此时叠加 1.5s 淡出，听感是**音乐被关掉了**，不是**曲子讲完了**。

而落款「册子合上了，路还长。剩下的，你自己去看。」是周爷爷这条叙事线的**唯一一次落幕**。用一个中断在半句上的伴奏送走它，是本次唯一不可接受的听觉结果。终止式不是锦上添花，它是这句台词的标点符号。

### 1.2 `bgm_codex` 被**故意**设计成没有情绪曲线

`audio-direction.md` §4 白纸黑字：codex 轨的目标是「安静博物馆的展厅」，能量 0.40，平稳无推进；同章还写明 BGM 全程不做戏剧化推进，情绪高点**全部交给 SFX**。

但这段影片里**一个 SFX 都没有**（§5 已定翻帧音不做、进入音并入 BGM）。把一条「设计目标就是让人想不起它长什么样」的轨，放在全作情绪最高点、且是唯一声源的位置上——这是把方向文档的前提用反了。情绪曲线这次必须由 BGM 自己承担，`bgm_codex` 在设计上就不具备这个能力。

### 1.3 复用会当场作废「这是特别时刻」的信号

全收集玩家是**图鉴页的常住民**——他们刚刚为了集满 36 个实体在 codex 里进出了几百次。这条轨对他们是「图鉴的声音」。

更要命的是 §3.4 的重看入口就挂在 Hub / 图鉴页附近：玩家看完影片回到图鉴，**听到的是刚才那首曲子**。gain 从 0.42 掉回 0.40 这 0.4 的差，没有任何人能听出来。所谓「特别时刻的微弱信号」在这个上下文里等于零。

### 1.4 成本核算

| 项 | 数值 |
|---|---|
| 新增文件 | 1 个（`bgm_tour.mp3`） |
| 目标体积 | **≈ 530KB**（32.7s @ 128kbps 立体声），硬上限 700KB |
| 出曲成本 | MiniMax `music-2.6-free` 免费档，跑 3–5 条候选 |
| 代码改动 | 3 处注册表 + 1 处 `audioManager` 修复（§8） |

> 参照：现有 3 条 BGM 均为 256kbps，单文件 3.6–4.4MB，**合计 11.7MB**，已远超 `audio-direction.md` §5.1 的 ≤900KB/≤1.1MB 约定。`bgm_tour` 按 128kbps 交付，是不让这个坑继续扩大；存量 3 条的重编码建议见 §10 存疑项 D-3。

# 2. 声音人格与词表

## 2.1 人格延续，但换一个动作

沿用 **「温润青铜 · 展柜微光」**（`sfx-metallic-redesign.md` §0），但动作从「托起」变成「推开」：

> 前 22 个 SFX 的原型是 **Touched, not counted**（被触碰的，不是被清点的）。
> `bgm_tour` 的原型是 **Opened, not celebrated**（被推开的，不是被庆祝的）。
> ——像一位老人把窗户推开，让你自己看外面；他不在旁边鼓掌。

## 2.2 情绪词表（正向）

| 层级 | 词 |
|---|---|
| **核心三词** | 温润传承 · 旅行启程 · 文化好奇 |
| 质感 | 暖、旧、有呼吸、留白、克制、手工感、午后光线 |
| 动势 | 缓步向前、逐渐开阔、中途悬停、温柔落地 |
| 情感 | 被惦记着、有人替你准备过、不舍但要出发 |

## 2.3 反向词表（**生成时必须显式否定**）

| 类 | 禁 | 为什么这次特别危险 |
|---|---|---|
| **庆典类** | 庆典、颁奖、获胜、号角、fanfare、铜管、欢呼、鼓组进行曲、掌声 | 「全收集结算」这个语境天然吸引生成器往颁奖乐走。**这是本次最大生成风险之一** |
| **世界音乐拼盘** | 民族乐器串烧、地域风格切换、world music medley、西塔琴 / 钢鼓 / 尺八 / 排箫 / 手鼓 | ⚠ **本次最大生成风险**，见 §2.4 |
| 预告片类 | riser、impact、宏大编曲、弦乐爆发、电影预告感 | 与温情克制调性正面冲突（`audio-direction.md` §3.2） |
| 电子类 | 电子鼓、四四拍律动、EDM、loop 感的电子 pad 循环 | 工具 App 化 / 与手账语境冲突 |
| 金钱类 | coin / money / cash / treasure / prize / jackpot / win（独立词） | 合规红线，一票否决 |
| 人声 | 任何 vocals、哼唱、和声人声、儿童合唱 | `is_instrumental: true` 已兜底，prompt 再否一次 |

## 2.4 ⚠ 头号风险：「旅行 / 环游世界」会把生成器推向民族乐器拼盘

影片画面横跨日本、中国、坦桑尼亚、希腊、瑞士、墨西哥、智利、阿根廷。只要 prompt 里出现「环游世界 / 世界旅行」，生成模型极大概率产出**每 4 秒换一种民族乐器的拼盘**。

这不只是难听，**这是踩合规**：`audio-direction.md` §3.3 已明确否决「一件乐器代表一整个大洲」的方案，理由是**文化刻板印象**，对一款文化教育定位、面向儿童的产品构成实质品牌风险。`sfx-metallic-redesign.md` §2.3 甚至为此弃用了 `temple bell` 这个词。

**执行结论（不可协商）：**
1. prompt 里**只写「旅行」，绝不写「环游世界 / world tour / around the world」**；
2. prompt 里**显式否定**民族乐器串烧与地域风格切换；
3. 全曲**统一一套配器**，8 帧的情绪差异靠**密度与音区**表达，不靠换乐器；
4. 挑片时若听到任何可辨识的地域符号乐器（西塔琴、钢鼓、尺八、班卓、手风琴以外的地域标志音色）→ **直接废片重跑**，不做后期补救。

> 补充说明（避免误会）：主奏用**卡林巴**不违反 §3.3。卡林巴在本作是**全局通用主奏**（`audio-direction.md` §3.1 白名单首位，hub / match / codex 全用它），不承担任何区域标记职能。判定标准是「这件乐器有没有被用来指代某个地区」，不是「这件乐器起源于哪」。

## 2.5 配器（全部取自 `audio-direction.md` §3.1 白名单）

| 层 | 乐器 | 职责 |
|---|---|---|
| 主旋律 | 卡林巴（拇指琴） | 主题动机，短句留白 |
| 副旋律 | 八音盒 | 主题的「远处回声」，用于开阔段与高位点缀 |
| 和声 | 毛毡钢琴 + 暖弦垫（低通 ≤ 4kHz） | 铺底，承载情绪起伏 |
| 脉动 | 尼龙弦吉他（指腹轻拨，无甲片） | 「行走」的低密度节奏感，**非节拍器式** |
| 点缀 | 颤音琴（软槌）、极轻青铜风铃 | 呼应展柜微光人格；用量必须极省 |
| 空气 | 极轻室内空气声 | ≤ −30dB |

**明确不进这条轨**：任何打击乐组、任何铜管、手风琴（`audio-direction.md` §3.1 将其限定为「里程碑与章节完成」专用色，本轨不借用，避免与 `sfx_chapter_complete` 抢语义）。

# 3. 结构与时间轴

## 3.1 与影片时间轴逐段对齐

影片时长按 `world-tour-reward.md` §2.3 逐段相加：`2.0 + 8×3.4 + 3.5 = 32.7s`。

> ⚠ 任务书口述的「展开 2–29.5s / 收束 30–33s」是约数。**以下用 §2.3 的精确算术，因为它直接驱动淡出触发点。**

| 段 | 影片本地时钟 | 画面 | 音乐动作 |
|---|---|---|---|
| **起手** | **0 → 2.0s** | 黑场渐亮 + 主文案 | 从近乎无声中**涨潮式浮起**（swell）。暖垫 + 一记柔和木质气息。**无金属击发、无 bloom**（硬要求，见 §4） |
| **展开** | **2.0 → 29.2s** | 帧 1–8，每帧 3.4s | 主题陈述 → 逐渐开阔 → 中段悬停 → 收敛至最静。密度曲线见 §3.2 |
| **收束** | **29.2 → 32.7s** | 画面渐暗 + 落款淡入 | 终止式主和弦**落在 ≈29.2s**；运行时立即起 **1.5s 线性淡出**，t≈30.7s 归零 |
| **静默** | **30.7 → 32.7s** | 落款 + 署名在屏 | **纯静音，2.0s。这是设计意图，不是 bug** |

### 为什么最后 2 秒要全静音

落款署名是「—— 周爷爷，写在册子最后一页」。这是整部影片、也是整条叙事线的最后一个画面。

**在这一行下面留白，比配任何音乐都重**。玩家读完这句话时耳朵里什么都没有，那个安静本身就是这段内容的落点。第 8 帧字幕「那一下，海先安静了」也在语义上预告了它——音乐的静，是画面里那片海的静。

> ⚠️ **给 engineering-lead 与 QA：这 2 秒静音不要「修」。** 如果真机走查后主理人觉得空得慌，唯一的调法是把淡出起点从 29.2s 后移到 30.2s（静音缩到 1.0s），**不要改成用 BGM 填满**。旋钮见 §8.3。

## 3.2 八帧情绪色（**挑片依据，不是生成指令**）

> ⚠ **必读**：MiniMax 是单 prompt 一次性生成，**不可能**逐帧受控。下表**不是**写进 prompt 的内容，它的用途有两个：① §7 挑片时的打分标尺；② 若需人工微调时的编辑依据。写进 prompt 的只有「起 → 展开 → 悬停 → 收」这条粗曲线（§5）。

| 帧 | 时间 | 名胜 / 字幕核心 | 情绪色 | 理想的配器动作 |
|---|---|---|---|---|
| 1 | 2.0–5.4 | 富士山 · 浪与山 | 启程，第一次抬头 | 主题动机首次陈述，卡林巴短句，极简 |
| 2 | 5.4–8.8 | 长城 · 一步步走出来 | 步履、绵长 | 尼龙弦拨弦进入，给出行走脉动 |
| 3 | 8.8–12.2 | 乞力马扎罗 · 赤道的雪 | 开阔、意外 | 弦垫首次上抬，八音盒高位单音（雪冠） |
| 4 | 12.2–15.6 | 圣托里尼 · 白墙挡日 | 明亮、干燥 | 主题移交八音盒，空间稍开 |
| 5 | 15.6–19.0 | 少女峰 · 云替它说了 | 静、悬停 | **第一次留白**：拨弦停，只剩垫 + 一记风铃 |
| 6 | 19.0–22.4 | 霍奇米尔科 · 手种的浮田 | 温、人情 | 卡林巴回归，颤音琴对位，最暖的一段 |
| 7 | 22.4–25.8 | 摩艾 · 望着远方 | 沉、敬意 | 低音下沉，主题以长音陈述，密度开始收 |
| 8 | 25.8–29.2 | 鲸 · 海先安静了 | **全片最静** | 一条持续音 + 一记极远的青铜泛音，为终止式蓄势 |
| 收 | 29.2– | 落款 | 落地 | 主题最后一次完整终止式，落主和弦 |

**这条曲线的形状**：起 → 走 → 开 → 亮 → **停** → 暖 → 沉 → **静** → 收。
**两个静点（帧 5、帧 8）是这条曲线的骨架**。一条从头满到尾、没有呼吸的曲子，无论多好听都不合格——它会让 8 帧看起来一样长。

## 3.3 硬性结构约束

1. **一次性，不循环。** 必须 `loop: false`（§8 有代码 blocker）。
2. **无缝 loop 要求不适用。** `audio-direction.md` §5.2 的无缝循环规范对本轨**豁免**——它从设计上就只播一遍。这同时绕开了该文档 §9 标注为「⚠ 存疑」的 mp3 loop 接缝问题：**本轨天然不受影响**。
3. **最后 1.5s 必须是自然衰减尾**，不能是硬切。运行时淡出叠在自然衰减上，听感才是「收住了」而不是「关掉了」。
4. **总时长 ≥ 30.7s**。低于此则淡出触发时音乐已经结束，会出现「先静音、再淡出」的空转。理想 32.7s（与影片等长），32.7s 以上多出的部分永远不会被听到，无害但浪费体积。

# 4. 起手音：与 `sfx_win_session` 的强制区分

## 4.1 关键决策：**不新增 `sfx_tour_open` 事件**

`world-tour-reward.md` §5 建议「一记低音量的柔和起手音」。**我的定案：这一记起手音就是 `bgm_tour` 自己的前 2 秒，不做成独立 SFX。**

理由不是省事，是**新增一个 SFX 反而会放大它想解决的问题**：

- 一个新的 P0/P1 起手 SFX 会在 `openWorldTour()` 那一帧起播，而此刻 `sfx_win_session` 的青铜琶音尾 + 星 pip 可能仍在衰减中（玩家点「继续」的间隔完全不可控，快的话 1 秒内）。**这正是 `clear-sfx-presence-fix.md` §0 记录过的同一个坑**：同族音色前后脚起播，听感糊成一团分不出层级。
- 影片开场本来就是 2 秒黑场渐亮。**一段渐强的 BGM 起手，本身就是最好的「进入音」**——它有 2 秒的时间从 0 长起来，天然不会和任何正在衰减的 SFX 撞上瞬态。
- 成本：0 个新事件、0 个新文件、0 条新降级表条目。

## 4.2 区分对照表（**出曲与挑片的硬验收项**）

`sfx_win_session_01` 现行规格（`sfx-metallic-redesign.md` §3 B 组 / `clear-sfx-presence-fix.md` §4.2）：
`warm three note metal chime arpeggio played with soft mallets, then a paper folder closing softly` · 1.8s · 归一化后峰值 **−5.1 dBFS**。

| 维度 | `sfx_win_session`（局末通关） | `bgm_tour` 起手（0–2.0s） | 区分度 |
|---|---|---|---|
| **材质** | 青铜钟琴（金属，带 shimmer 尾） | 暖弦垫 + 木质气息，**零金属** | ★★★ 决定性 |
| **包络** | 击发型：瞬态 → 衰减 | **涨潮型**：1.5–2.0s 渐强，无瞬态 | ★★★ 决定性 |
| **音区** | 中高（钟琴 + 小铃 pip） | **中低**（低弦泛音 + 中音木质） | ★★ |
| **音高走向** | 上行三音琶音 | 单一持续音，微沉后托起 | ★★ |
| **起始电平** | 峰值 −5.1 dBFS，一上来就满 | **从 0 起**，2.0s 后才到 0.44 目标 | ★★★ 决定性 |
| **时长** | 1.8s 一发即止 | 持续 32.7s | — |

**三个「决定性」维度任一成立就足以分层；本设计三个全占。** 结论：只要起手段**不含任何金属敲击**，撞车在物理上不可能发生。

> 🔴 **写进 prompt 的硬否定**：`不要闪亮的金属敲击开场`、`不要铃声或钟琴起头`、`不要一上来就响`。
> 🔴 **挑片一票否决项**：候选曲若在前 2 秒内出现任何**钟琴 / 铃 / 三角铁 / 金属敲击**，无论后面多好听——**废片**。这一条没有折中。

# 5. MiniMax 出曲 Prompt（成品，可直接抄）

> 端点 `POST https://api.minimaxi.com/v1/music_generation`，模型 `music-2.6-free`，`is_instrumental: true`，`output_format: "url"`（24h 失效，需脚本下载落盘）。

> 🔴 **必须带 `--only bgm_tour`。** 裸跑会重跑全部 4 条并**就地覆盖已交付的 `bgm_hub` / `bgm_match` / `bgm_codex.mp3`**。
> **本项目当前不在 git 版本控制下**（`/Users/albert/Documents/GameDream` 无 `.git`），这三条 11.7MB 的资产**只存在于磁盘上，没有任何版本备份**；而 MiniMax 生成是非确定性的 —— 同一条 prompt 重跑得到的是**另一首曲子**，不是同一首。**一旦覆盖，永久不可复原。**
> 脚本目前只在裸跑时打 `console.warn` 然后继续执行，不拦截。唯一的挽回窗口是首次 API 返回前的 30–60 秒内 Ctrl-C。

- 日志标 `[精简 prompt]` 的候选 = 走了降级路径，**挑片须按 §7 A 组从严**（精简版砍掉的正是负面词覆盖度，A2 民族乐器拼盘的防线最薄）。

# 6. 后期处理规格（拿到原始曲之后）

MiniMax 的输出**不会**直接满足交付标准，以下三步必做。

## 6.1 目标值

| 项 | 目标 | 依据 |
|---|---|---|
| 时长 | 32.7s（可接受 30.7–35s） | §3.3 |
| Integrated Loudness | **−20.5 LUFS** | 对齐 `bgm_codex` 实测 −20.7 LUFS，见下 |
| True Peak | **≤ −1.5 dBTP** | `audio-direction.md` §6.2 |
| 编码 | mp3 / 44.1kHz / **128kbps 立体声** | §1.4 体积 |
| 目标体积 | ≈ 530KB，硬上限 700KB | §1.4 |

> **为什么响度目标钉在 −20.5 而不是随便归一**：实测 `bgm_codex` = **−20.7 LUFS**。把 `bgm_tour` 做到 −20.5，配合 gain 0.44 vs 0.40（= +0.83 dB），玩家实际听到的差值 ≈ **+1.0 dB**——刚好是「察觉得到但说不出来」的量级，这才是「特别时刻」该有的信号强度。若素材响度自己就飘了 3 LU，这个精心设计的 1 dB 就毫无意义。
>
> ⚠ 顺带记录一条实测问题：`bgm_codex.mp3` 真峰值 **+0.4 dBFS**（已削顶，超 `audio-direction.md` §6.2 的 −1.5 dBTP 约定 1.9 dB）；三条 BGM 响度跨度 5.0 LU（−17.6 / −20.7 / −22.6）。**不属本次范围**，登记在 §10 存疑项 D-3。

## 6.2 ffmpeg 配方

**第一步 · 定位裁切窗口（人工听）**
MiniMax 大概率不会精确给 33s。先听出一个**以自然终止式结尾**的窗口，记下起点 `START`：

```bash
ffprobe -v error -show_entries format=duration -of csv=p=0 bgm_tour_take1.mp3
```

**第二步 · 裁切 + 响度归一 + 编码（单次转码，一步到位）**

```bash
ffmpeg -i bgm_tour_take1.mp3 \
  -ss <START> -t 32.7 \
  -af "afade=t=in:st=0:d=0.25,loudnorm=I=-20.5:TP=-1.5:LRA=9" \
  -c:a libmp3lame -b:a 128k -ar 44100 \
  minigame/assets/audio/bgm/bgm_tour.mp3
```

- `afade in 0.25s` 只是消除裁切点的咔哒声，**不是**§3.1 的 2 秒起手涨潮——后者必须由音乐本身写出来，不能靠 fade 伪造（fade 只能改音量包络，改不出配器逐渐加入的层次）。
- **不要**在这里烘焙结尾淡出。1.5s 淡出是**运行时**做的（§8.3），因为玩家跳过时也需要淡出，而跳过点不可预测。素材本身保留自然衰减尾即可。

**第三步 · 复核**

```bash
ffmpeg -hide_banner -nostats -i minigame/assets/audio/bgm/bgm_tour.mp3 \
  -af ebur128=peak=true -f null - 2>&1 | grep -E "Integrated|True peak" -A2
ls -l minigame/assets/audio/bgm/bgm_tour.mp3
```

验收：`I` 在 −20.5 ±0.5 LUFS，`Peak` ≤ −1.5 dBFS，体积 ≤ 700KB。

# 8. 给 engineering-lead 的落地

## 8.0 🔴 Blocker：`playBgm()` 硬编码了 `setLoop(true)`，忽略了注册表已有的（必填）`loop` 字段

`minigame/src/core/audioManager.ts` `playBgm()` 内：

```ts
const slot = this.createSlot(src, false, true, now);   // ← 第三参 loop 写死 true
...
slot.handle.setLoop(true);                              // ← 又写死一次
```

**它完全没有读 `AUDIO_EVENTS[cfg.track].loop`。** 因此只在注册表里给 `bgm_tour` 写 `loop: false` **不会生效**——影片播完后音乐会从头循环，直接毁掉 §3.1 的终止式设计（玩家会在落款静音段听到起手涨潮重新长起来）。

**必须先改成读定义：**（`playBgm` 在 L658 已用 `AUDIO_EVENTS[cfg.track]` 取过 def，只是没存变量、又写死 `true`；把已查到的 def 存成变量、两处 `true` 换成 `def.loop` 即可，**不新增任何字段**）

```ts
const def = AUDIO_EVENTS[cfg.track];
const slot = this.createSlot(src, false, def.loop, now);
...
slot.handle.setLoop(def.loop);
```

现有三条 BGM（`bgm_hub` L303 / `bgm_match` L315 / `bgm_codex` L327）都是 `loop: true`，且 `loop` 是 `AudioEventDef` 的**必填字段**（漏写编译不过）。**此改动对它们零行为变化**——代码已核，非设计推测，安全。新增 `bgm_tour` 条目按 §8.1 带上 `loop: false` 即可（必填，本就漏不掉）。

| 轨 | gain | 说明 |

## 8.2 播放控制要求

| # | 要求 | 后果（不做的话） |
|---|---|---|
| 1 | **不循环** | 见 §8.0 |
| 2 | **影片暂停 → BGM 同步暂停；继续 → 续播不重头** | `world-tour-reward.md` §2.4 的「单击暂停」是给玩家读长字幕用的。若 BGM 不跟着停，玩家暂停 20 秒读字，音乐照跑，终止式会**提前 20 秒**落掉，落款出现时已是死寂。**这条不做，§3.1 的设计就作废了** |
| 3 | 淡出用**影片本地时钟**（`gameTimeMs - tourStartedAt`），不用墙钟 | 与暂停语义一致 |

## 8.3 1.5s 淡出：需要一个新的公开 API

`audioManager` 目前没有可用的对外淡出接口——`rampMusicTo()` 是 `private`，且 `targetMusicGain()` 会在任何 duck / 音量变更时把音量重新算回来，直接调用会被覆盖。

**建议实现（照抄现成的 `duckFactor` 模式，约 10 行）：**

```ts
private tourFadeFactor = 1;   // 与 duckFactor 并列声明

// targetMusicGain() 末行乘进去：
//   clamp01(sceneGain * BUS_GAIN.MUSIC * (musicVolume/100) * this.duckFactor * this.tourFadeFactor)

/** 影片收束用：把 MUSIC 总线在 ms 内线性淡到 0（不停播，仅降增益） */
fadeMusicOut(ms: number): void {
  this.tourFadeFactor = 0;
  this.rampMusicTo(this.targetMusicGain(), ms, this.clock());
}

/** 离开影片时复位，否则下一条 BGM 永远是静音的 */
resetMusicFade(): void {
  if (this.tourFadeFactor === 1) return;
  this.tourFadeFactor = 1;
  this.rampMusicTo(this.targetMusicGain(), BGM_FADE_MS, this.clock());
}
```

**调用点：**

| 时机 | 调用 |
|---|---|
| 影片本地时钟到 **29200ms**（落款淡入同帧） | `audio.fadeMusicOut(1500)` |
| `closeWorldTour()` 开头（正常播完 / 跳过 / 返回，**三条路径都要**） | `audio.resetMusicFade()` |

> 🔴 **`resetMusicFade()` 漏调 = 全局静音 bug。** `tourFadeFactor` 是乘进总增益的，不复位的话玩家看完影片回 Hub 后**所有 BGM 永久静音**，而且刷新后复现（因为它每次进影片都会再被置 0）。这是本次接线**最容易漏、后果最严重**的一处。**请在跳过路径上单独测一遍。**

**建议抽成常量**（放 `audioEvents.ts` 与 `BGM_FADE_MS` 同区），方便走查调音：
```ts
/** 影片收束淡出触发点（影片本地时钟 ms）= 2000 + 8×3400 */
export const TOUR_BGM_FADE_START_MS = 29200;
/** 影片收束淡出时长 */
export const TOUR_BGM_FADE_MS = 1500;
```
§3.1 提到的「末 2 秒静音太空」的唯一调法，就是把 `TOUR_BGM_FADE_START_MS` 后移到 `30200`。

## 8.4 重看入口的音画对齐（`openWorldTour(replay = true)`）

> ⚠ **本节的「字面实现」不是假设，而是已在代码里**：`src/data/worldTour.ts` `tourPhaseAt()`（约 L204）`const intro = replay ? 0 : TOUR_INTRO_MS;` 把重看的 2s 整段抹掉，正是下面警告的字面版。等 `bgm_tour` 落地就会炸——`TOUR_BGM_FADE_START_MS = 29200` 是单一常量，重看时落款 27200 就出来、淡出却等到 29200，且全片 30700 结束会砍掉素材最后 2 秒（终止式）。临时版 `bgm_codex` 在循环、无终止式可砍，playtest 抓不到。**这是已存在缺陷，不是待实现项；无论方案 A / B 都必须改。** 补丁已备：方案 A 涉及 **3 文件 5 处**——`data/worldTour.ts` 去 `replay` 参数（L203）+ L204 改 `const intro = TOUR_INTRO_MS`、`app.ts` L423 与 `render/worldTour.ts` L331 两处调用点去第 2 参、`render/worldTour.ts` L347 intro 分支加 `if (!app.tourReplay)` 包住文案。（`replay` 在 `tourPhaseAt` 内彻底不再使用，索性移除——与 §8.0 的 `loop` 同一类「看起来在用、其实死了」的问题；黑场底在分支外，只去文字不动绘制顺序。）待主理人拍板即落。

`world-tour-reward.md` §3.4 说重看时**跳过开场 2s 主文案**。若照字面实现（影片直接从帧 1 开始）而音乐仍从 0s 播，**音乐会整体晚 2 秒**——终止式落在帧 8 中间，落款出现时音乐还在展开段。§3.1 精心对齐的时间轴当场作废。

| 方案 | 做法 | 评价 |
|---|---|---|
| **A（推荐）** | 重看时**保留 2s 开场时长**，只是**不显示主文案**——黑场渐亮 + BGM 起手照旧 | 时间轴零改动、零风险；2 秒黑场配一段渐起的音乐，本来就是更好的重入体验 |
| B | `innerAudioContext.startTime = 2.0` / `seek(2)` 后起播 | 需要 seek，安卓 `InnerAudioContext` 的 seek 精度与回调时序不可靠，**不建议为省 2 秒冒这个险** |

**建议采 A。** 如果主理人坚持重看要更快进入，那就把开场压到 1.0s，**同时**把 `TOUR_BGM_FADE_START_MS` 在 replay 分支减 1000 —— 但这就引入了两套时间轴；实测字面版代价是音乐晚 2 秒、终止式被整段砍掉（见本节顶部「已存在缺陷」标注），远不止省下的这 1 秒。
