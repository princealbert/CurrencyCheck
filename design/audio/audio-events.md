# 1. 命名与分类约定

## 1.1 命名约定

沿用现有资产的 snake_case 风格（对齐 `assets/cur_${iso}_${denom}_${region}_${form}.png`）：

```
音效：  sfx_<组>_<动作>[_<变体序号>]      例：sfx_card_flip_02
背景乐：bgm_<场景>                        例：bgm_match
```

- **事件 ID = 文件名（不含扩展名）**，一一对应，杜绝映射表漂移；
- 变体后缀为两位数字 `_01` `_02` `_03`，运行时随机选取；
- 全小写，仅用 `a-z0-9_`。

## 1.2 优先级定义

与 `dialogueEngine` 的 `DialoguePriority` 口径一致（**数值越小优先级越高**），便于工程侧统一理解：

| 级别 | 语义 | 打断行为 | 同发上限内被丢弃顺序 |
|---|---|---|---|
| **P0** | 仪式性、一次性 | 打断同组一切；其余 SFX 组 duck ×0.5 持续本音时长 | 永不丢弃 |
| **P1** | 关键正反馈 | 打断同组 P2/P3 | 永不丢弃 |
| **P2** | 常规交互反馈 | 不打断，可叠加 | 后丢弃 |
| **P3** | 装饰性 | 不打断 | **首先丢弃** |

## 1.3 表头字段说明

- **触发时机**：`文件:行号 / 函数` 为现有代码锚点（v1 尚无音频代码，此处为**建议插桩点**）。
- **时长**：素材长度上限，含尾音混响。超长即退回重做。
- **循环**：`单次` / `循环`。
- **变体**：需交付的素材个数（≥2 时运行时随机选，防机关枪感）。
- **节流**：同事件最小间隔，低于此间隔的触发被丢弃。

# 3. B 组 · 对局交互（总线 `SFX.GAMEPLAY` ×1.00）

| # | 事件 ID | 触发时机（代码锚点） | 音色方向 | 时长 | 循环 | 优先级 | 变体 | 节流 |
|---|---|---|---|---|---|---|---|---|
| B1 | `sfx_card_flip` | 翻牌点击命中帧（`app.ts` `flipCard()` 入口，**不等** `FLIP_MS=300` 动画结束） | 硬卡纸翻面 + 极轻木片轻碰；干、无尾音 | **120–180ms** | 单次 | P2 | **3（必须）** | 50ms |
| B2 | `sfx_card_flipback` | 错配翻回，`t0 + MISMATCH_FLIPBACK_MS(800)` | 同 B1 但更闷、略下行；**两张卡共播一次，不双发** | 140–190ms | 单次 | P3 | 2 | — |
| B3 | `sfx_match_miss` | 错配判定帧，`app.ts:544`（`trigger('MATCH_MISS')` 同帧） | 颤音琴柔和**下行小三度**二音 + 极轻空气声 | 250–350ms | 单次 | P2 | 2 | — |
| B4 | `sfx_match_success_repeat` | 已收集币种配对成功，`app.ts:523` 分支 | 卡林巴**上行**二音，温暖、克制 | 350–450ms | 单次 | P2 | 3 | — |
| B5 | `sfx_combo_step` | 连击 ≥2 时叠加于 B4/C1 之上（`match.combo` 递增帧） | 玻璃琴单 pip，音高随 combo 递升，**5 级封顶**后不再升 | 100–140ms | 单次 | P3 | 5（音阶级） | — |

> **B1 必须 3 变体 + 运行时 ±1.5 半音随机微调。** 对局中最高频的音就是翻牌（T3 环球 18 对 = 至少 36 次翻牌）。单一素材连发 3 次以上会立刻产生「机关枪感」，是本清单中最容易翻车的一条。
>
> **B3 音色红线**：错配音**禁止**使用下行大跳、噪声爆发、蜂鸣。参照册册的错配台词语气——「（轻轻摇头）不是一对。再看看——」，音效必须与这个语气同温度。
>
> **B5 可选**：`sfx_combo_step` 属装饰层，「减少动态音效」开启时整体静默（见 §7）。

| # | 事件 ID | 触发时机（代码锚点） | 音色方向 | 时长 | 循环 | 优先级 | 变体 | 节流 |
|---|---|---|---|---|---|---|---|---|
| C1 | `sfx_match_success_new` | **新币首次**配对成功，`app.ts:516` 分支（`firstTime && !wasCollected`），判定帧 t=0 | 卡林巴**上行三音** + 八音盒尾光 | 700–900ms | 单次 | **P1** | 2 | — |
| C2 | `sfx_unlock_codex` | 自动入册（同一 `firstTime` 分支），对齐粒子 `BURST_AT = 370ms` | **盖章**：木质闷响（章落纸）+ 上扬玻璃泛音尾 | 600–800ms | 单次 | **P1** | 1 | — |
| C3 | `sfx_win_session` | 一局完成，`app.ts` `finishWin()` | 温暖三和弦琶音（毛毡钢琴）+ 纸页收拢 | 1.2–1.6s | 单次 | **P1** | 1 | — |
| C4 | `sfx_star_pip` | 胜利面板星星**逐颗**点亮（`starsFor()` 结果 0–3 颗） | 玻璃琴单音，三颗依次**上行**（`_01`/`_02`/`_03` 音高递增） | 280–350ms/颗 | 单次 | **P1** | **3（音高级）** | — |

## 4.1 关键编排 · 新币解锁瞬间的三音叠加

这是全作情绪最高点，也是最容易糊成一团的时刻。现有代码在此已有三条时间线（`fx.ts` 常量 + `dialogueEngine` delay），音频必须严格挂靠：

```
t = 0ms     判定帧：firstTime && !wasCollected
            ├─ C1 sfx_match_success_new  ─────────────┐ (P1, 700-900ms)
            │                                          │
t = 370ms   BURST_AT：粒子爆发                          │
            ├─ C2 sfx_unlock_codex  ──────────┐        │ ← C1 尾音仍在
            │                                  │        │
t = 570ms   BURST_AT + UNLOCK_TOAST_DELAY      │        │
            └─ MATCH_SUCCESS_NEW 对白入队       │        │
               └─ E1 sfx_dialogue_pop  ✂ 抑制  │        │   ← 见抑制规则
                                                ▼        ▼
```

**抑制规则（写入 AudioManager）**：`sfx_dialogue_pop` 触发时，若**前 400ms 内**播放过任何非 `SFX.UI` 组音效 → **跳过**。

理由：t=370 的 C2 与 t=570 的 E1 相隔仅 200ms，三音连发会把「盖章入册」的仪式感冲垮。抑制后此刻只剩 C1+C2 两层，正是设计意图的「上行报喜 + 落章确认」。

**头空要求**：C1 与 C2 在 t=370–900ms 区间完全重叠，两者叠加后 True Peak 必须 ≤ −3 dBFS（`audio-direction.md` §6.2）。**必须在素材阶段留好**，运行时无限幅器。

## 4.2 胜利面板星评编排

```
t = 0ms     finishWin() → C3 sfx_win_session (1.2-1.6s)
t = 350ms   ★1 点亮 → C4 sfx_star_pip_01
t = 570ms   ★2 点亮 → C4 sfx_star_pip_02      (间隔 220ms)
t = 790ms   ★3 点亮 → C4 sfx_star_pip_03
t = 500ms   MATCH_WIN_SESSION 对白 (delay:500, app.ts:540)
            └─ E1 sfx_dialogue_pop  ✂ 抑制（400ms 内有 star_pip）
```

- 只播实际获得的星数（`earnedStars` 0–3）；0 星不播 C4。
- ⚠ **待程基岩确认**：上表 350ms/220ms 为音频侧建议值，需与 `renderer.drawWin()` 星星点亮动画的真实时间轴对齐。若动画时序不同，**以视觉为准**，音频跟随。

# 6. E 组 · 叙事（总线 `SFX.NARRATIVE` ×0.80）

| # | 事件 ID | 触发时机（代码锚点） | 音色方向 | 时长 | 循环 | 优先级 | 变体 | 节流 |
|---|---|---|---|---|---|---|---|---|
| E1 | `sfx_dialogue_pop` | 册册 toast 开始 enter 动画（`host.enqueueToast()` 出队播放帧，`TOAST_ENTER_MS=200`） | 极轻书页翻动 + 一枚温柔木质 pip | 180–260ms | 单次 | P2 | 2 | **400ms** |
| E2 | `sfx_hub_first_open` | 首次进入 Hub，`app.ts:192`（`trigger('S1_HUB_FIRST_OPEN')` 同帧） | 行囊搭扣轻响 + 书页展开 + 长尾暖垫 | 1.5–2.0s | 单次 | **P0** | 1 | 一生一次 |

## 6.1 E1 是册册的「声音签名」

`audio-direction.md` §8.1 已定 v1 不做 VO。E1 因此承担册册的全部听觉身份——玩家将通过这一枚音建立「册册要说话了」的条件反射。**因此 E1 的音色一致性优先级高于其独特性**：宁可平淡，不可每次不同。2 个变体仅为极轻微的呼吸变化，不得有可辨识差异。

## 6.2 E1 抑制规则（汇总）

E1 在下列任一条件成立时**跳过**（不入队、不排队补播）：

1. 前 **400ms** 内播放过任何非 `SFX.UI` 组音效（覆盖 §4.1 / §4.2 的解锁与胜利场景）；
2. 同一批 toast 的**第 2 条及以后**（册册叙事常一次推 2–3 行，`pendingLines` 逐行喂入 —— 只在**该批第一行**响一次）；
3. 「减少动态音效」开启（§7）。

第 2 条尤其重要：`MATCH_SUCCESS_NEW` 的 `discoveryLine` 是 3 行逐行播放（约 10s），若每行都 pop 一次，册册会从「陪伴者」变成「通知栏」。

## 6.3 与 12 个对白节点的关系

`dialogueEngine` 的 12 个节点**全部共用 E1**，不为单个节点定制音效。已有更强反馈的节点（`MATCH_SUCCESS_NEW`→C1/C2、`MATCH_WIN_SESSION`→C3、`REGION_COMPLETE`→D2、`S1_HUB_FIRST_OPEN`→E2）由抑制规则自动让位。

|---|---|
| `S1_HUB_FIRST_OPEN` | **E2**（E1 抑制） |
| `S1_HUB_RETURN` | E1（若当日触发 D3 里程碑则抑制） |
| `MATCH_FIRST_TUTORIAL` | E1 |
| `MATCH_SUCCESS_NEW` | **C1 + C2**（E1 抑制） |
| `MATCH_SUCCESS_REPEAT` | **B4**（E1 抑制，B4 在 400ms 内） |
| `MATCH_MISS` | **B3**（E1 抑制） |
| `MATCH_WIN_SESSION` | **C3 + C4**（E1 抑制） |
| `CODEX_OPEN` | A5 → E1（A5 属 UI 组，不抑制 E1） |
| `PROFILE_OPEN` | A1 → E1 |
| `PASSPORT_TEASER` | A1 → E1 |
| `REGION_COMPLETE` | **D2**（E1 抑制） |
| `RATE_SNAPSHOT_NUDGE` | E1 |

# 10. 异常与兜底（对齐现有资产加载模式）

现有 `preloadImages()` / `preloadScenes()` 采用 fire-and-forget + `.catch()` 静默降级（`app.ts:692` / `:712`）。音频**必须沿用同一契约**：

1. **素材缺失 / 解码失败** → 该事件静默，不抛异常、不阻塞、不重试，游戏逻辑完全不受影响；
2. **音频系统整体不可用**（旧机型 / 权限异常）→ 全局静默降级，所有 `play()` 变为 no-op；
3. **同发数超上限**（见 implementation §3.4）→ 按 §1.2 优先级丢弃，P3 先丢，P0/P1 永不丢；
4. **切后台** → 全部暂停；回前台仅恢复 BGM，**不补播**积压的 SFX；
5. **快速连点** → 由节流列（§2–§6 表末列）拦截；
6. **对局中途返回 Hub** → 立即停止全部 GAMEPLAY 组音，BGM 交叉淡变到 `bgm_hub`。
