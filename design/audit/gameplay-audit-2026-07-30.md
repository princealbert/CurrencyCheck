# 货币图鉴 · 玩法审计与改进建议

> 审计视角：系统 / 机制设计师（十几年 RPG / 平台 / 射击 / 生存）
> 日期：2026-07-30
> 对象：MVP 原型（mvp/）+ 真实 Canvas 实现（minigame/）+ 设计文档（GDD / menu-ia / roadmap）
> 方法：先读代码与文档，再按 Fun Hypothesis → Design Pillars → 机制活检 逐层过

---

## 0. 结论先行

- **工程架构 A 级**：core 层纯函数 + 不可变状态、幂等解锁、平台 KV 注入、四层识别码双形态落地、合规纪律严格。这是能交付的地基，别动。
- **玩法乐趣 C+ 级**：所有"好玩"的假设都押在"发现新货币"上，但当前每局永远是同样 8 个币种、只是洗牌不同。玩家第 3 次玩就变成纯记忆复读，没有新东西可发现。
- **根因**：GDD 设计了 T1/T2/T3 难度阶梯 + 区域书架上下文入口 + v1.1 多元素关联配对，但**这些一个都没进代码**。`startPair(form)` 永远构建 16 张全量牌（8 对），`app.ts` / `hub.ts` 里根本没有 region 入口、没有难度参数。
- **一句话诊断**：你们把"对对碰的壳"做完了，把"货币图鉴的灵魂"留在了文档里。

## 1. Fun Hypothesis 复核

| 维度 | 设计意图（文档） | 当前实现（代码） | 落差 |
|------|----------------|---------------|------|
| 好玩核心 | 靠风格化特征**认出**货币，并发现其**真实世界锚点** | 通用记忆配对 + 货币皮肤；锚点只在详情页 | 灵魂未落地 |
| 愉悦发现 | 每次配对都可能在学新东西 | 每局内容恒为 8 币，无新变量 | 第 3 局即枯竭 |
| 可亲文化学习 | 100% 真实内容 + 分层文案 + 现实锚闭环 | 锚点存在但未在"学习时刻"触发 | 学习未闭环 |
| 轻松无限 | 无失败 / 无体力 / 广告不卡进度 | 达成（✅ 这部分做对了） | 无 |

**设计判断**：当前实现的真实 fun = "把 8 张脸背下来"。这不是"货币图鉴"，这是"贴了钱标签的通用对对碰"。差异化的全部潜力都在未实现的层里。

## 2. 做得好的（必须保留，别为了改而改）

1. **core 层纯函数 + 不可变状态**（`deck.ts` / `matchLogic.ts`）：`flip/evaluate/flipBack` 返回新 state，可单测、可推理。这是专业做法。
2. **幂等解锁**（`collectionStore.unlock`）：重复配对不重复计数，跨会话安全。正确。
3. **平台抽象**（`KVStore` 注入，browser/wechat 共用 core）：让同一套逻辑跑浏览器预览和微信真机，省掉 Cocos GUI 的坑。架构决策对。
4. **四层识别码双形态落地**（`card.ts`）：coin 圆牌金属质感、note 纸张质感、区域徽标角标区分都实现了，且**不依赖真实钞币图**。合规与美术方向都对。
5. **无失败态 / 连击仅奖励**（`matchLogic.ts`）：对齐"轻松无限"支柱，儿童友好。✅

## 3. 核心问题（按优先级）

### P0-1 · 局内多样性枯竭（最致命）
- **现象**：`buildDeck(CURRENCIES, form)` 永远推 8 币 ×2 = 16 张。`CURRENCIES.length` 恒为 8，没有任何会话级筛选。
- **后果**：第 1 局要记 8 个新东西（过载），第 5 局还是这 8 个（无聊）。memory-match 的乐趣来自"逐渐认识"，不是"永远同一组"。
- **修复方向**：见 §4 创意 D（区域书架作为难度入口）+ 扩充内容池（当前 8 币不足以支撑区域局：amer 仅 2、euro 仅 2、asia_afr 仅 4）。

### P0-2 · 难度阶梯 / 区域书架从未进入代码
- **GDD §1.⑦ / §1.④** 明确设计了 T1 单区 3×4（易）→ T2 → T3 6×6（难），以及 Hub 区域书架点击触发"单地区主题会话"。
- **代码现状**：`startPair(form: FormFactor)` 只收 form，无 region、无 tier。`hub.ts` 只有"开始配对 / 图鉴"两个按钮，无书架入口。
- **落差**：这是设计文档里最亮眼的差异化（"去金库发现新钱币"而非"开始一关"），但代码完全没有。

### P1-1 · 母题层塌陷 → 识别过度依赖颜色
- **数据事实**：`currencies.ts` 中 8 币有 **5 个 `motif: 'portrait'`**（USD/GBP/CNY/JPY/INR）。
- **GDD §6.3 规则 2** 要求"置灰②后靠①③④仍可区分任意两币"。但②母题类别几乎恒定，**真正的非颜色区分器只剩**：区域形状（仅 3 值，且 region 内不区分币种）+ ISO 文本 + 面额符号。
- **具体风险**：CNY（红 #C75D4F）vs INR（薰衣草 #B08FB5）同为 portrait、同为 asia_afr、同为面额 100，靠 ISO 文本和 ¥/₹ 符号救场——**颜色在扛识别的重活**。色弱玩家和"靠特征认出"支柱双输。
- **修复**：给每个币种**独立的母题几何符号**（不是 4 类，是 8 个差异化形状），让"特征"真正可辨，同时为后续"真实钞币母题迁移"铺路。

### P1-2 · 解锁瞬间零庆祝 → 北极星没被服务
- `app.flipCard` 里 `store.unlock` 触发了，但**配对过程中没有任何"你发现了一个新货币！"的反馈**。`anchor`（现实锚）只出现在 codex 单元格小字和 S5 详情。
- **后果**：游戏动作和"学习真实世界知识"完全脱钩，北极星（现实认得出）落空。
- **修复**：首次解锁时闪一条「现实锚」一句话（例："巴西雷亚尔 · 背面是绿翅金刚鹦鹉"）。既庆祝发现，又闭环学习，且是你们相对通用对对碰的**唯一护城河**。

### P1-3 · 分数 / 连击无设计意义（浪费信号）
- `score` 被显示、被存 best，但**不驱动任何事**。连击只有"数字变大"的反馈，没有"为什么我要连"的目标。
- **设计判断**：在"轻松无限"支柱下，不该加失败惩罚，但应该给**软 mastery 信号**。建议把分数改造成**无失败星评**：按本局失误数给 1–3 ⭐（⭐阈值见 §6，待 playtest）。给复玩目标，不施压。

### P2-1 · 收集完成后的留存钩子为空
- 16 个实体集齐后，"收集"这条元循环的唯一目标消失。无星评、无护照（锁定）、无 best-time。
- **短期**：星评 + 区域 mastery（每区单独 ⭐）。**长期**：roadmap 的护照 / 旅行 meta。

### P2-2 · 配对反馈偏弱（juicy 不足）
- `card.ts` 只有翻牌 + 错配（无 shake 动画实现，仅翻回）。成功配对后卡牌**原地常驻、无缩放/变暗/清除感**（`drawBoard` 里 matched 卡 `faceUp` 恒真，静态）。
- memory-match 的爽点之一是"棋盘 visibly 清空"。建议 matched 卡轻微缩放 0.92 + 降低亮度，让未配对区更聚焦。

## 4. 设计创意（让"货币图鉴"区别于通用对对碰）

### 创意 A · 元素关联配对（最高杠杆，且合规安全）
- **机制**：不只"同 ISO 配对"，而是"货币 ↔ 它的动物 / 景观 / 人物"。例如 BRL ↔ 绿翅金刚鹦鹉、ZAR ↔ 白犀牛、JPY ↔ 富士山。
- **合规**：全是风格化几何母题，无真实钞币图、无国旗（roadmap v1.1/v1.2 已规划，且 R 风险最低的 person/landscape/animal 可先于 flag 上线）。
- **教育价值**：这比"背相同两张"难忘 10 倍，直接服务北极星——玩家在现实中看到金刚鹦鹉会想起巴西雷亚尔。
- **实现钩子**：GDD §6.3 / roadmap 已留 `matchKeyOf` 注入点，`matchLogic.evaluate` 改为接受注入键即可。

### 创意 B · 首次解锁闪「现实锚」
- 配对成功且 `firstTime` 时，卡牌上方浮一条 1.5s 淡出的 trivia（复用 `anchor` 字段前 40 字）。零新增内容成本，闭环学习。

### 创意 C · 无失败星评
- 结算时按 `mismatchCount` 给 ⭐：0 失误 = ⭐⭐⭐，1–2 = ⭐⭐，>2 = ⭐。存每 (iso 区域/tier) 最佳星，Hub 展示。给 mastery 信号，不违反"轻松无限"。

### 创意 D · 区域书架 = 难度入口 + 内容扩张双解
- Hub 用 3 个区域书架替代/补充"开始配对"：点美洲→只玩 USD/BRL（易）；点"环球"→跨区混排（难）。
- **但前提**：当前 8 币撑不起区域局（amer/euro 各仅 2 币）。**必须先扩内容池到每区 ≥6 币**（roadmap v1.1 多元素本质也是扩池）。内容扩张是 P0 的依赖项，不是 optional。

## 6. 行动清单（按优先级）

| 优先级 | 动作 | 设计支柱对齐 | 验证信号 |
|--------|------|------------|---------|
| **P0** | 扩充内容池至每区 ≥6 币（共 ~18–24 实体） | 愉悦发现 / 可亲学习 | 单区局可 ≥6 对 |
| **P0** | 实现区域书架入口 + `startPair(form, region, tier)` | 愉悦发现 | Hub 可进单区局 |
| **P1** | 每币种独立母题几何符号（替换 4 类） | 靠特征认出 / 色弱友好 | 置灰②仍可区分 |
| **P1** | 首次解锁闪现实锚（创意 B） | 可亲学习 / 北极星 | 玩家能复述锚点 |
| **P1** | 分数 → 无失败星评（创意 C） | 轻松无限 | 复玩率↑ |
| **P2** | 元素关联配对模式（创意 A） | 全部三支柱 | 留存↑ |
| **P2** | matched 卡视觉清除感 + 解锁 burst | 愉悦发现 | 手感爽度 |
| 文档 | 同步 GDD §6.1（当前写"仅 coin 3×4"，实为双形态 4×4） | 一致性 | 文档=代码 |

> ⭐ 星评阈值（P1-3）为 **[PLACEHOLDER · 待 playtest 验证]**：建议先按 `mismatchCount` 分 0 / 1–2 / >2 三档，A/B 测试后调阈值；未跑 playtest 前不承诺具体档位。
