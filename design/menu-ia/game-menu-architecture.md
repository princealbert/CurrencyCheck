# 游戏菜单信息架构提案（游戏范式）

> 文档类型：架构提案（不改 ardot 视觉稿，仅提案）
> 项目：微信小游戏 · 对对碰货币配对（memory-match currency）
> 作者：文策渊（设计 + UX/交互）
> 状态：待主理人 / 开发者审批
> 范围：MVP 信息架构；旅行护照锁定为未来拓展
> 依赖参考：现有 4 屏 ardot 视觉稿（Home / Play / Passport / Me）；合规红线（ISO 4217 代码非国旗、几何母题非真实纸币、每日静态汇率 + 免责标注、区域双编码：美洲=圆角矩形+金 / 欧洲=六边形+蓝 / 亚洲·非洲=菱形+绿）

---

## 0. 执行摘要（TL;DR）

彻底**去掉底部 App Tab 栏**，改用「薄闪屏（仅冷启动）+ 中央 hub（落地页）+ 大号游戏风按钮 / 可进入空间」模型。
**中央 hub = 钱币收藏册（藏宝室 / 钱币工作室）**，是常驻基地、进度总览与行动中枢；配对玩法入口内嵌 hub（中央 CTA + 区域书架上下文启动）；护照降级为 hub 内「敬请期待」teaser，不进 MVP；「我的」重定义为「收藏家档案」（进度 / 成就 / 设置）。全 5 核心屏 + 1 可选闪屏。

---

## 1. 对用户观点的指正（Correct / Sharpen / Push back）

### 1.1 钱币收藏册当中央 hub 是否最优？—— ✅ 支持，但需 sharpen
- **支持**：收藏册同时是「元循环目标（配对→解锁）」「社交炫耀面」「主题一致性载体」，作 hub 是最优解。
- **Sharpen（关键）**：若把「收藏册」实现成**目录列表（list）**，骨架仍会像 App。必须做成**空间 / 叙事场景**（钱币工作室 / 藏宝室），用**区域书架（双编码）**承载，而非 tab 行。Hub 的「书」是玩家**住进去的地方**，不是设置面板。

### 1.2 是否还需要标题屏（title screen）？—— 🔧 修正（pushback 冗余感）
- 微信小游戏语境下，传统「Press Start」标题屏**冗余且增摩擦**（微信即入口）。
- **建议**：冷启动仅 1–2s **品牌闪屏**（含合规微声明 + 加载）→ 直接进入 hub。**hub 即落地页**，不做独立常驻标题屏。品牌仪式感用 hub 顶部薄品牌条 + 当日汇率快照日期戳替代。

### 1.3 配对模式入口放哪？—— ✅ 这是关键问题，需明确
- 入口应双轨：**(1) hub 内一个大号「开始配对」CTA（主行动）**；**(2) 各区域书架可「翻开该地区」触发主题配对（上下文式）**。
- 这样配对 = **「去金库发现新钱币」**，而非「开始一关」。避免把 Play 孤立成 tab 导致与收集脱节。

### 1.4 「我的」菜单应符合游戏设定—— ✅ 支持
- 重定义为**「收藏家档案」**，承载：收集进度 / 成就徽章 / 图鉴完成度 / 设置（无障碍开关、广告偏好）。**不是个人主页**。

### 1.5 护照概念—— ✅ 支持保留为未来拓展（补充）
- 当前应**显式锁定为「敬请期待」态（teaser）**，不进入 MVP 范围，避免支柱漂移与范围蔓延；其旅游主题与广告内容可预先呼应。

## 2. 推荐的游戋范式信息架构（屏幕清单 + 游戏循环角色）

### 2.1 游戏循环（MDA）
**Discover（配对翻找）→ Unlock（解锁并自动收藏图鉴条目）→ Showcase（收藏炫耀 / 社交）→ 回访**
元循环由**收集进度**驱动。货币在首次成功配对后**自动收藏**（类似《原神》风物志式解锁），详情页不设手动“加入收藏”按钮；广告（旅游主题）作为**可选激励 / 赞助商**，不卡进度。

### 2.2 屏幕清单

| # | 屏幕 | 游戏循环角色 | 核心内容 |
|---|------|------|------|
| S0 | 品牌闪屏 Splash（仅冷启动） | 进入 + 合规微声明 + 加载 | 1–2s 品牌；「静态汇率非金融建议」微声明；自动进 hub |
| S1 | **中央大厅·钱币收藏册 Hub** | 常驻基地 / 落地页 / 行动中枢 | 收集进度总览；区域书架（双编码）；中央「开始配对」CTA；图鉴 / 档案快捷入口；每日汇率快照条；护照 teaser 槽 |
| S2 | 配对玩法 Match Session | 核心动作屏（机制层） | 快速配对 + 区域主题配对；翻牌 / 错配 / 胜出反馈；胜→发现动画→新图鉴条目 |
| S3 | 钱币图鉴 Codex | 收藏 / 炫耀面（美学层） | 浏览已发现货币；文化 / 历史 / 设计小传；静态汇率；社交展示（截图分享） |
| S4 | 收藏家档案 Collector Profile | 进度 / 成就 / 设置（游戏向） | 完成度 %、徽章、无障碍开关、广告偏好；非个人主页 |
| S5 | 旅行护照 Travel Passport | 锁定 / 敬请期待（未来拓展） | teaser 展示旅游主题联动（与广告呼应）；不进 MVP |

> 注：S0 为可选（冷启动一次性）；MVP 核心为 S1–S4，S5 为锁定占位。

---

## 2.3 收藏机制：自动解锁（风物志式）

- **解锁即收藏**：玩家在配对玩法中首次成功匹配某货币后，该货币自动加入「钱币图鉴」与「收藏家档案」进度；无需任何手动确认或「加入收藏」按钮。
- **详情页为纯阅读态**：S3 货币详情页只展示文化小传、静态汇率、区域信息等阅读内容，底部不再放置「加入收藏」等离散动作按钮，保持图鉴/风物志的沉浸阅读感。
- **未解锁态**：未发现的货币在图鉴中以占位剪影（silhouette + ISO 代码问号）呈现，激发玩家通过配对玩法解锁。
- **进度正反馈**：解锁瞬间通过「发现动画」+ 收藏册/档案数字变化强化元循环，避免传统“点击收藏”的额外摩擦。

## 3. 结构建议（是否去掉 Tab？）

**推荐：彻底去掉底部 App Tab 栏，采用 hub 中心化模型。**

- **结构**：薄闪屏（仅冷启动）+ 中央 hub（落地）+ 大号游戏风按钮 / 可进入的空间。
- **导航逻辑**：靠「进入场景」而非「切换分栏」。hub 永远可返回；S2/S3/S4 是从 hub「走进去」的房间。
- **理由**：
  1. 小游戏留存靠**低摩擦 + 沉浸**；常驻 tab 持续提醒用户「在用 App」，削弱游戏感。
  2. 大按钮 + 空间隐喻（书架 / 工作室）提升 tactile 反馈与 juicy 感。
  3. hub 即进度页，首屏即「你的收藏状态」，比 App 式首页更符合休闲配对游戏的动机曲线。

**不推荐**保留 Tab 的折中方案（如 hub + 底部 2 个常用入口）——会重新引入 App 语境，违背本次重构目的。

## 5. 简短 UX 注记（游戏感 vs App 感）

- **Juicy 反馈**：翻牌物理、配对「叮」+ 闪光、错配抖动、发现解锁爆发——微动画即游戏感。
- **进度线索无处不在**：「已收集 47 / 200」常驻；区域完成环。
- **首屏即进度**：落地 = 你的收藏状态，不是欢迎语 / 营销主视觉。
- **收藏册隐喻**：把整个游戏当物理「书 / 室」来居住，不是列表滚动；空间书架而非 tab 行。
- **大号游戏风按钮**：有触感 / 阴影 / 按压态，区别于扁平 App tab。
- **去常驻 tab** = 「你在游戏世界里」而非「用分栏 App」。
- **广告内世界化**：旅游主题广告框为「旅行见闻 / 赞助商」，保持沉浸，不破坏合规与叙事。

---

## 6. 设计红线检查

- **合规**：hub / 图鉴用 ISO 4217 代码非国旗；几何母题非真实纸币；每日静态汇率 + 免责标注（快照条 / 图鉴内）。
- **主导策略**：避免「只有快速配对」成唯一正解 → 区域配对给图鉴完成奖励，使收集元循环成为目标。
- **经济失衡**：单人收集无真经济；广告**不卡进度**，仅可选激励（提示 / 装饰）。
- **认知过载**：hub 不过载——区域书架 + 渐进揭示，不一次性列 200 币。
- **支柱漂移**：护照未来功能不泄漏进 MVP；三支柱（愉悦发现 / 可亲文化学习 / 轻松无限）每屏对齐。
