# 游戏感视觉方向：从「工具 App」到「环球钱币收藏册」

> 文档：`design/art/game-feel-direction.md` · 作者：林绘澄（美术/视觉）
> 适用项目：《货币图鉴·对对碰》纯 TS + Canvas 2D 微信小游戏
> 性质：**纯设计配方文档，不含代码改动**。所有配方以当前 `card.ts` / `theme.ts` / `renderer.ts` 实现事实为基准编写，工程可直接照抄数值落地。
>
> **合规铁律（全篇有效）**：所有材质与场景均为风格化抽象处理。绝不建议、绝不包含真实钞币图样、硬币照片、国徽、国旗、人物头像、防伪元素（水印/安全线/凹版纹）。「金属」「纸张」仅指抽象光影与肌理，不指向任何真实币种的物理外观。

---

# 1. 诊断：为什么现在「像 App」

三条根因，按影响排序：

1. **背景是纯色平涂，无场景感。** `renderer.ts drawApp` 对所有视图统一 `fillRect(THEME.bg)`（#F8F5F0）。纯奶油白 + 白面板（#FFFFFF）+ 浅灰线（#E7E1D6）正是移动端工具 App（记账/待办类）的标准配方。游戏需要「场所」——收藏册摊在桌上、卡牌摆在绒面上——目前没有任何一层在讲这个故事。

2. **卡牌无材质、无厚度，读作「贴纸/图标」。** `drawFaceCoin` 的外环是区域色单色平涂 + 一道孤立的白弧；`drawFaceNote` 是纯白卡片加色框。没有受光方向、没有倒角、没有纸基色温，硬币读作塑料徽章、纸币读作名片。用户反馈「硬币不像金属、纸币不像钱」根因即在此：**色彩身份系统是对的，缺的是材质层。**

3. **信息层级是「排版」而非「舞台」。** Hub 标题是裸文本（`fitText('货币图鉴', ...)`），进度是矩形条，按钮是白底圆角矩形——全部是 UI 组件语言，没有任何一个元素在用「游戏道具」的语言说话（绶带、印章、书脊、旅行手账）。层次上所有元素几乎同一投影深度，无景深。

**结论**：不需要推翻现有四层识别码与调色板（它们是资产），需要补三件事——**场景底（§3）、材质层（§4/§5）、游戏化框架（§6）**。

# 2. 游戏化视觉方向（总纲）

## 2.1 调性定位：「旅行者的钱币手账」

一本被主人带着环游世界的收藏手账：暖纸底、手工感印刷、彩色珐琅纪念章、盖章式进度。关键词：**温暖、手工、收藏欲、翻页感**。

- **不是**拟真钱包/银行 App（冷、白、精确）；
- **不是**赌场金币风（俗、饱和、闪烁）；
- **是**「Monument Valley 的克制配色 × 旅行手账的纸感 × 珐琅徽章的材质」。

三个抽象意象贯穿全部视图（详见 §6.4）：

| 意象 | 表达 | 出现位置 |
|---|---|---|
| 手账纸 | 暖白渐变 + 极低 alpha 纤维颗粒 | 所有背景、纸币卡面 |
| 珐琅章 | 区域色金属环 + 受光渐变 + 倒角 | 硬币卡面、区域徽标 |
| 旅程印记 | 绶带标题、印章角标、节点式进度 | Hub / Codex / Detail |

## 2.2 调色板：保留身份，升级层次

现有四色（奶油白 #F8F5F0 / 陶土红 #D89575 / 青绿 #87A878 / 金 #E0B15E）与区域三色（金 #E0B15E / 蓝 #5B8FB0 / 绿 #87A878）**全部保留**，不动任何身份色。升级方式是给每个身份色配「光影三度」，供渐变与倒角取值：

| 基色 | 亮部（受光，混白 ~30%） | 基准 | 暗部（背光，混墨 ~18%） |
|---|---|---|---|
| 金 #E0B15E | #F0D095 | #E0B15E | #B8904A |
| 蓝 #5B8FB0 | #8FB5CE | #5B8FB0 | #47738F |
| 绿 #87A878 | #AECBA2 | #87A878 | #6B8A5F |
| 陶土 #D89575 | #EBB89E | #D89575 | #B0765C |

背景族新增「暖纸系」（均由奶油白向暖黄偏移，非新身份色）：
`#FBF7EE`（纸亮）/ `#F3E9D8`（纸基）/ `#EDE6D8`（桌面）/ `#E8D9BE`（纸暗）/ `#E6DCC9`(桌暗)。

统一**光照约定**：全局光源在**左上方约 135°**（即左上亮、右下暗）。所有渐变、倒角、投影方向必须遵守这一条，这是「材质感成立」的第一前提——方向乱了就退回贴纸。

# 3. 各视图背景氛围配方

通用规则：
- 渐变用 `createLinearGradient` / `createRadialGradient`（微信 Canvas 2D 均支持；**不要用 conic gradient**，兼容性不稳）。
- 程序化纹理**必须预渲染到离屏 canvas 小瓦片**（建议 96×96），运行时 `createPattern` 或平铺 `drawImage`，**严禁每帧随机撒点**（脏 + 耗性能）。
- 所有纹理 alpha 上限见各条；总原则：**纹理是「凑近才看见」的，一眼看见就是脏了**。

## 3.1 Hub（S1 收藏册封面）——「暖手账纸」

- **底**：垂直线性渐变（0,0 → 0,vp.h）：
  `0.0 → #F3E9D8`，`0.55 → #EDE0C8`，`1.0 → #E8D9BE`。
- **颗粒**：纸纤维瓦片（见 §3.5 配方 A），整体 alpha **≤ 0.04**。
- **暗角**：径向渐变，圆心 (vp.w/2, vp.h*0.42)，内半径 min(vp.w,vp.h)*0.45 处 `rgba(90,70,40,0)`，外半径对角线*0.75 处 `rgba(90,70,40,0.06)`。上限 **0.06**，再高会显旧显脏。
- 效果：标题区最亮、四角微暖压暗，天然形成「封面聚光」。

## 3.2 Board（S2 对局）——「柔和桌面/绒面」

- **底**：垂直线性渐变：`0.0 → #F0E9DB`，`0.5 → #EDE6D8`，`1.0 → #E6DCC9`。
- **绒面纹**：斜纹瓦片（见 §3.5 配方 B），alpha **≤ 0.03**（比 Hub 更低——对局中背景必须绝对安静，不与卡面争眼）。
- **暗角**：径向渐变，圆心屏幕中心，从 60% 半径 `rgba(58,58,56,0)` 到边缘 `rgba(58,58,56,0.10)`。上限 **0.10**——Board 的暗角可以比 Hub 重，它的职责是把视线收进牌桌中央。
- 卡牌投影配套加强（见 §6.3），两者叠加后卡牌读作「摆在桌面上」而非「浮在白屏上」。
- 注意：横屏提示遮罩（rgba(58,58,56,0.55)）与胜利结算遮罩（0.62）已存在且更深，暗角不与其冲突。

## 3.3 Codex（S3 图鉴三区域书架）——「册页/书架暖底」

- **底**：同 Hub 渐变（#F3E9D8 → #E8D9BE），保持「同一本手账」的连贯。
- **书架带**：三个区域分区各加一条「架板」语言：
  - 每个区域分区底部画 1 条 2–3px 横线，`rgba(139,115,85,0.22)`，线下再叠 4px 高的渐变 `rgba(139,115,85,0.08) → 0`（架板厚度暗示）；
  - 每个分区背景比页面底**再亮一档**：分区矩形内垂直渐变 `rgba(251,247,238,0.5) → rgba(251,247,238,0)`（像册页比封面浅）。
- **区域色点缀**：各分区标题左侧一枚小色块/印章点（区域色，直径约标题字高 0.8），把 REGION_COLORS 从卡面延续到书架结构上。
- 颗粒同 Hub（alpha ≤ 0.04），暗角同 Hub（≤ 0.06）。

## 3.4 Detail（S5 详情）——「聚焦展台」

- **底**：同 Hub 渐变（保持手账连续性）。
- **聚焦压暗**：径向渐变，圆心 = 大卡牌中心，内半径 = 卡牌外接圆半径 × 1.25 处 `rgba(58,58,56,0)`，外缘（对角线）`rgba(58,58,56,0.12)`。上限 **0.12**（四视图中最深，Detail 的全部意义就是「只看这一枚」）。
- **展台暗示**（可选，成本 ≈ 0）：卡牌正下方画一个扁椭圆接触影：`ellipse(cx, cardBottom + h*0.03, cardW*0.42, cardW*0.06)`，径向渐变 `rgba(58,58,56,0.16) → 0`。一个椭圆就能把「浮着」变「摆着」。

## 3.5 程序化纹理瓦片配方（预渲染，两种）

| | A. 纸纤维（Hub/Codex/Detail/纸币卡面） | B. 绒面斜纹（Board） |
|---|---|---|
| 瓦片尺寸 | 96×96 离屏 canvas | 96×96 |
| 内容 | 随机 55–70 个元素：70% 为 1px 圆点、30% 为长 2–4px 随机角度短线 | 45° 平行短线，间距 6px，每条长 3px、断续排布 |
| 颜色 | `#8A7F68` | `#8A7F68` |
| 单元素 alpha | 0.5–1.0 随机（在瓦片内） | 1.0 |
| **整体叠加 alpha 上限** | **0.04** | **0.03** |
| 生成时机 | 启动时一次，缓存 | 同左 |

叠加方式：`ctx.globalAlpha = 0.03~0.04` + `createPattern(tile,'repeat')` 填充全屏（或直接平铺 drawImage），画完立即恢复 `globalAlpha = 1`。

# 4. 硬币金属材质配方（核心，风格安全）

> 目标：`drawFaceCoin` 的外环从「塑料色环」变成「彩色珐琅纪念章的金属托」。
> 合规：以下全部是渐变/描边/弧线的抽象光影，**不引入任何真实硬币图样、纹章、齿边计数、人物元素**。

现有结构保留：区域色外环 → 奶油内盘 → 高光弧 → 母题色圆盘 → 区域徽标 → ISO/面额。以下按绘制顺序给改造层（① 之后插入，序号对应落地顺序）：

## 4.1 外环「金属受光」渐变（在区域色 fill 之后叠加）

在区域色圆填充后、内盘覆盖前，对**同一个全圆**再叠一层 135° 线性渐变（左上亮 → 右下暗，内盘随后覆盖中心，只有环带露出）：

- `createLinearGradient(cx - R*0.7, cy - R*0.7, cx + R*0.7, cy + R*0.7)`，停靠点：
  - `0.00 → rgba(255,255,255,0.40)`
  - `0.30 → rgba(255,255,255,0.10)`
  - `0.55 → rgba(0,0,0,0.00)`
  - `1.00 → rgba(0,0,0,0.20)`
- 直接以该渐变 fill 同一圆路径（source-over 即可，无需换合成模式）。

效果：三个区域色各自变成「受光的彩色金属」，且身份色不变（亮暗部即 §2.2 表中的推导值）。

## 4.2 币缘倒角（厚度的关键，两道细描边）

- **外缘阴影线**：`arc(cx, cy, R - 0.75px)` stroke，`rgba(0,0,0,0.18)`，lineWidth `max(1, R*0.018)`。
- **内缘高光线**：`arc(cx, cy, R - inset + 0.75px)`（即环带内边界，奶油内盘外沿）stroke，`rgba(255,255,255,0.50)`，lineWidth `max(1, R*0.015)`。
- 可选第三道（预算允许时）：内盘外沿再内 1px 一道 `rgba(0,0,0,0.10)`，形成「高光-暗线」对，倒角立刻成立。

## 4.3 金属光泽弧（替换现有单弧）

现有 `Math.PI*1.12 → 1.42` 白弧保留位置逻辑，升级为**主弧 + 副弧**（不用 conic gradient，用两段 arc stroke，兼容性最稳）：

- **主弧（左上受光）**：`arc(cx, cy, R - inset*0.5, Math.PI*1.08, Math.PI*1.48)`，lineWidth `max(1.5, R*0.03)`，`rgba(255,255,255,0.65)`，lineCap round。
- **副弧（右下反光，金属回光的标志）**：`arc(cx, cy, R - inset*0.5, Math.PI*0.12, Math.PI*0.38)`，lineWidth 同上 ×0.7，`rgba(255,255,255,0.18)`。
- 一主一副、一强一弱、对角呼应——这是「金属」区别于「塑料」的最小笔画数表达。

## 4.4 内盘微穹面（奶油内盘从平涂改径向渐变）

- `createRadialGradient(cx - R*0.15, cy - R*0.18, R*0.1, cx, cy, R - inset)`：
  - `0.0 → #FDFAF3`（受光顶）
  - `0.7 → #F6F0E2`
  - `1.0 → #EFE7D6`（盘缘）
- ink #3A3A38 在最暗档 #EFE7D6 上对比度 ≈ 8.9:1，ISO/面额文本仍远超 WCAG AA，无需改字色。

## 4.5 母题圆盘「珐琅镶嵌」内阴影（可选增强）

母题 PNG/signature 圆盘绘制完、`restore()` 之后：

- 沿母题圆再 stroke 一圈 `rgba(0,0,0,0.14)`，lineWidth `max(1.5, mr*0.05)`，**并把 stroke 半径缩进 lineWidth/2**（让暗线压在盘内侧 = 内阴影错觉）；
- 圆盘下缘（`Math.PI*0.15 → 0.85`）补一道 `rgba(255,255,255,0.30)` 细弧（lineWidth `max(1, mr*0.03)`），即「凹槽下沿反光」。
- 两笔合计把母题从「贴上去的圆贴纸」变成「嵌进金属托的珐琅面」。

## 4.6 明确的合规边界

本节全部配方 = 渐变 2 个 + 描边弧线 ≤ 6 道。不出现：齿边（edge reeding）、年份、拉丁铭文环、任何真实硬币的构图引用。区域徽标（白圆+洲形状）与四层识别码逻辑**完全不动**。

# 5. 纸币纸张材质配方（核心，风格安全）

> 目标：`drawFaceNote` 从「白卡片 + 色框」变成「暖白钞基风格的印刷卡」。
> 合规：不含水印、安全线、凹版底纹、面值网纹等任何防伪语言；「印刷感」仅由双细线内框 + 纸色 + 纤维颗粒构成。

## 5.1 设计语言转向：从「色框卡」到「印刷纸」

现状是区域色整圈边框带 + 纯白内衬——这是「卡片」语言。改为「纸基 + 角部印记」语言：

- **区域色整圈边框 → 收窄为细边线**：外轮廓仍为区域色，但 `inset` 视觉上收窄（区域色只露出约 1.5–2px 细边），身份色不丢但不再是「相框」；
- **区域身份主载体改为「角标印章」**（见 §5.6），更贴近钞票设计中「角部面额区」的抽象化——注意这只是版式借意，不是复刻。

## 5.2 纸基填充（替换纯白/奶油内衬）

内衬矩形改 165° 近垂直线性渐变（`createLinearGradient(rect.x, rect.y, rect.x + rect.w*0.15, rect.y + rect.h)`）：

- `0.0 → #FBF7EE`（纸亮）
- `0.6 → #F6EEDD`
- `1.0 → #F0E8D6`（纸暗）

左上亮右下暗，与全局 135° 光照一致。

## 5.3 纤维纹理

复用 §3.5 配方 A 的纸纤维瓦片，clip 在内衬圆角矩形内平铺，整体 alpha **≤ 0.04**（与背景同瓦片、不同 alpha 亦可：卡面 0.04、背景 0.035，卡面略高一档让「纸感」在卡上更可读）。

## 5.4 印刷内边框（双细线，装饰性裁切线，非防伪线）

- **外线**：距内衬边缘 4px，圆角矩形 stroke，颜色 = 区域色 @ `alpha 0.45`，lineWidth 1px；
- **内线**：距内衬边缘 6.5px，stroke `rgba(58,58,56,0.16)`，lineWidth 0.75–1px；
- 双线间 2.5px 空隙即「印刷装订留白」。四角不加任何花纹（花角易滑向真钞装饰语言，禁止）。

## 5.5 厚度投影

- 卡牌整体 `withShadow(THEME.shadow, blur = rect.h*0.10, dy = rect.h*0.035)`（现为 blur `h*0.07`, dy 3——加深一档）；
- 可选「纸边」笔画：内衬下边缘 + 右边缘各 1px `rgba(0,0,0,0.08)` 直线（纸的裁切厚度），成本两条线。

## 5.6 母题「印刷视窗」+ 区域角标印章

- **母题横带 → 印刷视窗**：位置尺寸不变（`y+h*0.32`，高 `h*0.4`），绘制后沿视窗圆角矩形 stroke 一圈 `rgba(0,0,0,0.12)`（lineWidth 1.5px，半径内缩使暗线压内侧），视窗外再让 0.5–1px 纸色亮线露出（可用 `rgba(255,255,255,0.4)` 1px stroke 在暗线外侧）——「凹进纸面的印刷图版」错觉；
- **区域角标印章**：右上角现有区域徽标（白圆 + 洲形状）**升级为印章质感**：白圆改为区域色 @ alpha 0.15 的圆底 + 区域色 1.5px 圆环（外圈），洲形状仍为区域色实心。似「盖上去的墨章」而非「贴上去的图标」。徽标位置、洲形状、四层识别码逻辑不变。

## 5.7 明确的合规边界

不出现：人物/头像窗、水印区、安全线（竖向亮线/虚线是硬禁区）、缩微文字、团花/扭索纹（guilloché）。允许的全部元素 = 暖纸渐变、低 alpha 颗粒、双细线框、角标印章、母题视窗描边。

# 6. 去 App 化的游戏化手法清单

## 6.1 标题游戏化：绶带徽章框架（Hub）

「货币图鉴」从裸文本升级为**绶带横幅**（纯 Canvas 原语，约 3 路径）：

- 主体：圆角矩形横幅（宽 ≈ 标题宽 + 56px，高 ≈ 字号 × 1.7），填充陶土红 #D89575，叠 §4.1 同款 135° 受光渐变（白 0.25 → 黑 0.12），上下沿各 1px 金色 #E0B15E @ alpha 0.6 细线；
- 两端「燕尾」：横幅左右各接一个梯形/三角折角（同色系暗部 #B0765C），即绶带垂尾；
- 文字奶油白 #FBF7EE，`withShadow` 轻投影；
- 副标题「对对碰 · 世界各国货币」保持裸文本置于绶带下方，形成主次。
- 降级方案（若工期紧）：不做绶带，仅在标题左右各加一枚菱形/圆点金色装饰（`◆ 货币图鉴 ◆` 的图形化，用 path 不用字符），加一条 60px 宽金色短划线在下方——两笔即可脱离「App 页标题」感。

## 6.2 进度游戏化：从进度条到「收集之旅」（可选建议）

- **轻量版（推荐先做）**：现有矩形条改「胶囊 + 铆钉」：圆角半径 = 高/2；轨道色从 #E7E1D6 改 `rgba(139,115,85,0.18)`；填充青绿保留但加受光（上半 `rgba(255,255,255,0.25)` 半高覆盖条）；填充头部加一枚小圆「硬币游标」（金 #E0B15E 圆 + 1px 白高光弧，直径 = 条高 × 1.8）。
- **完整版（后续迭代）**：进度条改为三段节点路径（对应三区域），每段端点一枚区域色小徽章，解锁满段位则徽章点亮（受光渐变）未满则 locked 灰——把「进度」讲成「旅程盖章」。
- 文案「已解锁 12 / 32」保留（数据可读性不牺牲）。

## 6.3 层次景深：统一投影阶梯

现有 `withShadow` 直接可用，补一张**阶梯表**（工程可提为 theme.ts 常量）：

| 层级 | 用途 | blur | offsetY | 颜色 |
|---|---|---|---|---|
| E1 静置 | 面板、按钮、书架卡 | `h*0.08`（min 3） | `h*0.02`（min 1.5） | THEME.shadow (0.14) |
| E2 卡牌 | Board 卡、Hub 入口大按钮 | `h*0.10`（min 4） | `h*0.035`（min 2.5） | THEME.shadow |

规则：**同一视图内最多出现两级**；被按下的元素降一级（可留给交互迭代）。

## 6.4 「收藏册」母题贯穿

- **面板缝线**：白面板（胜利结算、Detail 信息卡）沿内缘 6px 画一圈虚线 stroke（dash [4,4]，`rgba(139,115,85,0.15)`，1px）——手账缝线感，一行 `setLineDash` 的成本；
- **卡背升级**：现有中性灰绿卡背（#D7DEDA + '?'）加同款受光渐变（白 0.18 → 黑 0.08）与 1px 内缘亮线，让卡背也像「章」而不是「灰圆」；'?' 保留；
- **页面页码/页眉**（可选）：Codex 顶部加一条居中短划线 + 两侧小圆点（`—— ● ——` 的图形化），册页感；
- **白面板底色微调**：THEME.panel 从 #FFFFFF 微调至 #FDFBF6（暖白），panelLine 从 #E7E1D6 调至 #E3D9C6——两个 hex 的改动，全 UI 立刻从「App 白」滑向「手账纸白」，且不破坏任何对比度。

## 已知冲突点 / 风险（工程落地前须知）

1. **`Ctx2DLike` 接口未暴露 `createLinearGradient` / `createRadialGradient` / `createPattern` / `setLineDash`**（与 `shadow*` 同样情况）。建议照抄 `theme.ts` 中 `CtxWithShadow` 的本地类型增强 + cast 模式，或在 `platform/types` 扩接口——需程基岩定夺，二选一均可。
2. **纹理必须预渲染瓦片**：离屏 canvas 创建走平台适配层（wx `createOffscreenCanvas` vs web `document.createElement`），需在 platform 层加一个 `createOffscreenCanvas(w,h)` 能力。若短期不想动 platform 层，§3 颗粒层可全部先跳过（渐变 + 暗角已完成 80% 氛围），颗粒作为二期。
3. **性能**：渐变对象建议按视口尺寸缓存（尺寸不变不重建）；卡面渐变在 4×4=16 张卡下每帧重建也可接受（脏矩形/dirty 标记已有），但若后续加动画常驻重绘，建议缓存到卡面离屏图。
4. **`drawFaceNote` 的 §5.1 区域色边框收窄**会轻微改变卡牌配色面积比例——区域识别性由「角标印章」补偿，需在真机上核对三区域在 4×4 棋盘上的一眼区分度；若识别性下降，回退为「细边 + 角标」双保险（本文档默认方案即是双保险）。
5. **对比度**：所有文本底色最暗档（#EFE7D6 / #F0E8D6 / #E8D9BE）与 ink #3A3A38 对比度均 > 8:1，WCAG AA 无风险；唯一需注意绶带上的奶油白字（#FBF7EE on #D89575 ≈ 2.6:1），**绶带字号必须 ≥ 24px bold 并加投影**，或把绶带底色压深至暗部 #B0765C（≈ 3.9:1）——推荐后者。
6. **不与文字出界修复任务冲突**：本文档不改任何 `fitText` / 文本布局逻辑，仅背景与图形层。
