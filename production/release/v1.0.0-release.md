## 1. 发布清单（Release Checklist · 提审前置）

### 1.1 应用类目建议

- **首选类目**：`游戏` → `休闲游戏`（或 `益智`）。本作为 memory-match 休闲配对玩法，归此最稳。
- **资质材料**：微信小游戏上线需《计算机软件著作权登记证书》（软著）+ 所选类目对应资质。建议以「休闲益智」类目 + 软著上线。
- **⚠️ 类目红线（必须规避）**：
  - **绝不**选「金融 / 理财 / 财经 / 投资」类目——会触发资金相关严审，且与微信内「红包 / 赚钱版」克隆混淆，正中合规雷区。
  - **绝不**在类目或简介中出现「提现 / 赚钱 / 红包 / 收益 / 理财」字样。
- **科普 / 教育定位**通过玩法与文案体现（风格化货币母题 + 100% 真实文化数据 + 静态汇率快照免责），**不强行挂在「教育」类目**下（避免额外资质门槛）；如主理人希望强化教育属性，可后续单独评估「教育」类目资质。

### 1.2 隐私协议（《微信小程序隐私保护指引》）

- **必须配置**：微信公众平台「设置 → 服务内容 → 用户隐私保护指引」须填写并审核通过；自 2023 年起须接入隐私接口（`wx.requirePrivacyAuthorize` / 隐私授权弹窗），首次调用涉及隐私的接口前弹窗授权。
- **本作数据实际采集**（均为本地存储，不上传任何个人信息）：
  - 音频设置（静音 / 音乐音量 / 音效音量 / 减弱动态音效）——存储键 `currency-codex-settings-v1`
  - 图鉴收藏进度、world tour 已看标记——本地 `collectionStore` / `metaStore`
  - 色弱模式偏好
- **隐私指引填写要点**：声明仅使用「本地存储」能力、不收集个人身份信息（PII）、不上传服务器；若未来接入广告（微信流量主），须在指引中补充「广告identifier」用途并保留授权弹窗。
- **提审前置动作**：隐私指引提交审核 + 代码中接入隐私授权弹窗（建议由 engineering-lead 在 wx 适配层补 `wx.requirePrivacyAuthorize` 调用）。

### 1.4 🔴 包体积治理方案（重点）

当前 wx 包实测 **≈81 MiB（即约 84 MB）**，分布：货币母题 PNG ≈62MB + 背景 ≈7.4MB + deco ≈0.4MB + 音频 ≈13.6MB + game.js ≈0.3MB。微信硬上限为**主包≤4MB、总包（主包+分包）≤30MB**。详见 §2 完整论证。

**两条路线对比速览**

| 路线 | 包内残留 | 质量损失 | 额外基建 | 合规/运营弹性 | 推荐度 |

| **A 资产全 CDN** | game.js + 配置 ≈ **0.3MB**（≪4MB） | 零 | 对象存储 + CDN + 域名备案 + 白名单 | 高（资产热更免复核） | ★ 推荐 |

## 2. 分包 vs CDN 论证（推荐路线）

### 2.1 微信体积限制事实

| 限制项 | 微信小游戏硬上限 |
|---|---|
| 主包（首包） | **≤ 4 MB** |
| 单个分包 | ≤ 20 MB |
| 主包 + 所有分包 **合计** | **≤ 30 MB** |

> 关键点：**分包提升的是「单包」上限（4MB→20MB），但「总包 30MB」 aggregate 上限不变。** 这是「仅分包」无法解决本问题的根因（见 §2.4）。

### 2.2 路线 A：资产全 CDN

- **做法**：包内只留 `game.js` + `game.json` + `project.config.json`；货币图 / 背景 / deco / world tour 帧 / 音频全部运行时从 HTTPS CDN 拉取。
- **所需基建**：对象存储（COS/OSS）+ CDN 加速 + **域名 ICP 备案** + 微信后台合法域名白名单（图像→downloadFile；音频→服务器域名/媒体域名）。
- **代码支撑**：`preloadImages`/`preloadScenes`/`getTourFrame`/`audioManager` 已为异步 + 缺失降级设计：母题 404→几何占位、背景 404→L0 暖色渐变、音频 404/解码失败→静默 no-op，游戏逻辑零影响。
- **优点**：① 包体极小（≈0.3MB），过审无虞；② 零质量损失；③ 资产热更能免重新提审，利于 Live Ops 与后续扩池；④ 与 world tour 既有 CDN 架构同构，统一不双路径。
- **代价**：需 CDN 基建 + 备案 + 白名单；首启依赖网络（已被占位/缓存缓解）；弱网体感须真机回归；CDN 流量成本（极低）。
- **前置回归**：浏览器预览走本地 assets，无法覆盖 CDN 失败路径，须用①临时 base 指向可达 CDN 跑真机；②断网/坏 base 模拟 404 验降级；③开发者工具「不校验合法域名」弱网开关（真机仍需白名单）。对应 C1–C12。

### 2.3 路线 B：分包 + 激进压缩进包

- **做法**：主包 ≤4MB（game.js + 入口配置），分包放 **pngquant/JPEG 激进压缩**后的图像 + **重编码（降码率/单声道）**音频；分包单包 ≤20MB、总包 ≤30MB。
- **所需基建**：无 CDN、无备案外链。
- **致命体积账**：总资产 ≈84MB，扣主包 4MB 后分包可用空间仅 **≈26MB**。需把 84MB 压进 26MB（≈**3.2× 压缩**）：货币图 62MB 压到 ~18MB、音频 13.6MB 重编码到 ~5MB、背景+deco 压到 ~3MB——**极度临界且质量损失大**（粉彩主色 / 母题细节受损，直接削弱产品核心价值「迁移识别」）。
- **优点**：无需 CDN 基建；下载后完全离线可玩。
- **代价**：质量损失大、体积临界（临界即风险）、未来加资产须重新打包 + 重新提审、无法热更。

### 2.4 为何「仅分包不解决总上限（30MB 含分包）」

分包机制只把**单包**上限从 4MB 抬到 20MB，但微信对**主包+所有分包的总和**仍封顶 30MB。本作总资产 ≈84MB，即便不压缩、全拆分包，总和 84MB ≫ 30MB，**依然顶穿**。要进包就必须「分包 + 激进压缩」把 84MB 塞进 26MB 余量——这就是 §2.3 的临界困境。**结论：「仅分包（不压缩）」在本体量下物理上不可行；「分包+压缩」可行但质量代价高、临界。**

### 货币图鉴 v1.0.0 · 首发更新说明

**这是一款关于「认识世界钱币」的休闲配对小游戏。** 我们用轻松的对对碰玩法，带你把各国货币认个遍——不是为了比拼手速，而是为了在某天真的见到一张外币时，你能会心地说一句：「这个我认得。」

**🎴 玩法**
- 经典记忆配对：翻开两张卡，凭**形状、母题色、ISO 代码、面额**找出同币种配对。
- 无失败态、无体力、无计时：连击只奖励，不惩罚。随时来一局，随时放下。
- 首次成功配对，对应币种即**自动收进图鉴**——奖励是「长出来的收藏」，不是分数。

**📖 图鉴与收藏**
- 收录 **18 个币种、36 个实体**（硬币与纸币两种形态各自成卡），覆盖美洲 / 欧洲 / 亚洲·非洲三大区域。
- 每张卡以**风格化原创母题**呈现（建筑 / 动物 / 人物等文化符号），不复制任何真实钞币图样；身份以 **ISO 4217 代码**为权威标识，区域用几何形状区分，不依赖国旗。
- 解锁后可阅读 100% 真实的文化与历史注脚：母题含义、建筑年代、动植物故事……把「认币」变成「看世界」。

### 4.3 灰度 / 全量
- **灰度**：微信小游戏支持分阶段发布（体验版 → 审核通过 → 分阶段放量）。建议先小流量灰度 1–3 天，监控崩溃率 / 留存 / 广告填充。
- **全量**：灰度指标平稳后全量发布。
- **分阶段回退**：微信支持「回退到上一版本」，无需重新提审（见 §4.4）。

### 4.4 回滚预案
- **保留上一可用包**：每次上传保留历史版本，出问题一键回退（微信后台「版本管理」）。
- **回滚触发条件**：真机崩溃率超阈值（如 >1%）、CDN 资产大规模拉取失败、重大合规投诉。
- **CDN 侧**：CDN 对象保留旧版本路径，必要时切回旧 CDN 前缀（base 常量灰度可控）。
- **降级兜底**：即便 CDN 全不可达，游戏仍以几何占位 / 渐变 / 静默运行，不白屏不崩溃（代码已具备）。

### 4.5 上线后监控
| 指标 | 关注点 | 预警 |
|---|---|---|
| 崩溃率 | 真机启动 / 配对 / world tour 崩溃 | > 1% 触发回滚评估 |
| 留存 | 次日 / 7 日留存 | 显著低于休闲游戏基准则排查首启体验 |
| 广告填充 | 旅游主题广告填充率 / eCPM | 填充率骤降排查广告位 / 合规 |
| CDN 健康 | 图像 / 音频拉取成功率、首屏耗时 | 拉取失败率升高排查白名单 / 备案 |
| 合规舆情 | 玩家反馈是否误读为「赚钱 / 投资」 | 出现即回应并复核文案 |
